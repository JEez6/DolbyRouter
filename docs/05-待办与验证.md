## D. 风险 / 回退

| 项 | 回退方式 |
| --- | --- |
| 强制普通轨导致音画不同步/卡顿 | 从名单移除该应用 |
| hook 崩溃目标应用 | 总开关关闭模块 / 删除模块目录后重启 |

## E. 方案决策（已定稿）

| 编号 | 问题 | 决策 |
| --- | --- | --- |
| F1 | 覆盖范围 | 只做 native 全量（Zygisk native module，统一覆盖 Java/OpenSL/AAudio） |
| F2 | 粒度 | per-app 按应用控制 |
| F3 | UI 语义 | 二值：`force_normal`（命中=挂杜比）/ `default`（放行） |
| F4 | 框架 | Zygisk native module（替代 Xposed/LSPosed） |
| F5 | 收口点 | `AudioTrack::createTrack_l()` 单点清 `mFlags` 的 FAST\|PRIMARY |
| F6 | MuseDash | 接受放弃杜比（其 OpenSL BufferQueue 对 FAST 时序敏感，转普通轨会卡） |

## F. 已知限制

- 实时低延迟 OpenSL 游戏（喵斯快跑等）：强制普通轨会卡顿，**不支持**（见 F6）。
- 仅 arm64-v8a 目标应用。
- 若系统升级改变 `libaudioclient.so` 布局/符号，偏移 `0x378` 需重新核对。
